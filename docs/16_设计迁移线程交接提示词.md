## 二、新设计稿的视觉系统

`export/css/tokens.css` 是移植依据。核心：

**七色，不新增**

| token | 值 | 用途 |
|---|---|---|
| `--paper` | `#f6f4ec` | 页面画布 · 暖纸 |
| `--ink` | `#1f2d25` | 正文标题 · 深墨绿黑 |
| `--yolk` | `#f6c945` | **唯一强调** · 缺口 / 主行动 |
| `--card` | `#fffdf8` | 卡片表面 |
| `--mist` | `#5d6b63` | 次要文字 |
| `--line` | `#dce3d9` | 描边分隔 |
| `--sage` | `#cbd4cc` | 次级行动 |

派生色全部用 `color-mix()` 从这七色调出，**不要在 Swift 里引入第八个颜色**。

**语义硬规则（不可改）**

- `--gap` = `--yolk`：缺口 / 还差一个 —— 全屏最高视觉权重
- `--ready` = `--ink`：已就位 / 已具备
- **缺口禁止用红色表达**。红只留给破坏性操作与真实错误。

**其余 token**：字号阶梯以 17px 正文为基准（Dynamic Type 基准）、4pt 间距基线、
圆角 8/14/20/28/pill、动效 `cubic-bezier(0.22,1,0.36,1)` 160ms/280ms、
Lulu 出场尺寸 hero 260 / header 120 / empty 170 / confirm 84 / avatar 44。

## 四、⚠️ 三个必须先知道的坑

### 坑 1：`azou` 是 API 契约词，不是资产名 —— 不要重命名

IP 形象从阿凑换成 Lulu，但后端契约里的 `azou` **必须原样保留**：

```
后端：onemore/modules/collab/service.py    sender_id="azou"、sender_type="azou"
接口：POST /channels/{channelID}/mention-azou
iOS： Repositories.swift:217 mentionAzou()、APIModels.swift:830 MentionAzouResult
```

全局搜索替换 `azou → lulu` 会**直接打断前后端契约**。
只改「用户可见的文案与图像」，不改字段名、端点、类型名。

### 坑 2：Lulu 的出场策略不能照搬素材来源项目

素材来自 Lulu's Kitchen，那边 Lulu 是**每个 Tab 的常驻陪伴**。
本产品红线 17 禁止「AI 主动闲聊、人格养成或维持活跃度的机制」，阿凑设定是「越早退场越好」。

**边界**：允许状态化出现（在听 / 在想 / 办成了 / 出问题了 / 退场）、替代空错态插画、品牌层；
禁止等级成长、喂养、亲密度、签到连续天数、主动发起对话、成局后常驻。

- **E7 协作空间是 Lulu 的退场点**，新设计稿已经把这句写在界面上了（「事办完了，我先走啦」）
- **E14 局内群聊 Lulu 不出场**

### 坑 3：20 条产品红线仍然全部有效

见 `docs/15_设计交接提示词.md` 第五节。迁移时最容易违反的：
不显示他人等级、招募未满员不显示报名人数、不显示已就位者身份、无已读回执与在线状态。

新设计稿本身是合规的（B12 底部还专门写了「席位只显示角色缺口，不显示已就位者是谁」），
**迁移时不要"顺手补充"这些信息**。

## 五、建议迁移顺序

1. **先立地基**：把 `tokens.css` 移植成新的 `OMTheme.swift`，
   再按 `css/app.css` 重建 `OMComponents` / `OMControls` / `OMStateViews`。
   这一步做完，后面每屏都是填内容而不是造轮子。

2. **G5 八个全局状态**（加载 / 空 / 网络错误 / 离线 / 权限拒绝 / 会话失效 / 重复点击 / 数据过期）
   作为一套系统先做完，避免每个页面各写各的。

3. **五个主 Tab**：B1 今天 → B12 比赛 → 差一个入口 → MSG 消息 → M1 我。
   做完这五个就能看出整体气质对不对。

4. **主链路**：D1 意图 → D2 澄清 → D3 意图卡 → D4 匿名池 → E3 多人确认 →
   E5 行动预览 → E6 执行结果 → **E7 协作空间（Lulu 退场）**。
   这条链路是产品的核心叙事，优先级高于长尾页面。

5. **其余节点**按 A / B / C / E / M / O / G 分组补齐。

## 七、当前构建里已知的缺陷（迁移应当一并修掉）

这些是在旧深色版本上实测到的，新设计稿都已经解决，迁移时注意别带过来：

| 节点 | 问题 |
|---|---|
| E6 执行结果 | 内容在 47% 处结束，之后约 440pt 纯黑，再砸一个全宽按钮 |
| C4 缺口卡落地 | **顶部与底部同时被裁切**——顶部文案被状态栏压掉，底部脚注被切 |
| D1 意图输入 | 阿凑立绘缩成看不清的小色块（缺 placement scale 约束） |
| B12 比赛 | 字号偏大，一屏只装得下 2.5 张卡；新稿同屏 3 张 + 完整 tab bar |
| 全局 | 主按钮用纯饱和 `#00FFE1` 平涂全宽，抢走全部注意力 |

根因在 `PrototypeScaffold.swift`：`ScrollView` 撑满剩余高度，内容少的屏留下大片空白，
`bottomAction` 再钉在最底。新设计稿的底部动作区是贴合内容的，迁移时按新稿走。
