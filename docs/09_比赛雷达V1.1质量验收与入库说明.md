## 1. 验收结论

V1 的结构、去重、时间格式和来源覆盖基础很好，但在“直接供前端组队”之前仍有四类问题：

1. 2 处会影响用户行动的事实/时间口径错误；
2. 学生直报、校内通知、学校统一报名三种入口被压成一个 `registration_url`；
3. 个人赛与团队赛共用“组队”动作，个人赛会生成 1 人局；
4. 商业主办赛事与学校、学会、行业组织赛事使用近似优先级，推荐顺序失真。

V1.1 已修正上述问题，并在数据库、API、意图编译、迁移、校验脚本和测试中形成闭环。

## 3. 推荐等级

推荐等级用于前端排序和运营露出，不替代 `verification_status=可行动`。

**存储与展示约定**（单一真相：`onemore/modules/competitions/recommendation.py`）：

| 存库/筛选码 `recommendation_tier` | 用户文案 `recommendation_label` | 数量 | 定义 | 处理方式 |
|---|---|---:|---|---|
| A | **优先推荐** | 14 | 中山大学/高校官方通知、学会或全国性行业组织官方通知，关键行动字段完整 | 默认优先展示 |
| B | **可报名** | 6 | 官方赛项页可核验，但赛事较新、组织或费用透明度相对有限 | 正常展示，临近报名再次核对 |
| C | **补充参考** | 4 | 商业机构主办，事实可核验但推荐价值较弱 | 补充区展示，默认降权 |

- 数据库与快照**只存**稳定码 `A|B|C`（`String(1)`），**不存**中文标签，避免文案变更触发全量迁移。
- 公开 API 在读路径派生 `recommendation_label` / `recommendation_description`。
- 筛选目录：`GET /competitions/recommendation-tiers`；列表筛选仍用 `?recommendation_tier=A|B|C`。
- **不是**比赛难度、含金量，也**不是**用户信任等级 T0–T4。

“经开杯”四项均保留事实数据，但降为 C 档。其官网明确主办方为创赛云（陕西）教育科技有限合伙企业；其中双创能力/英语词汇为个人付费赛，按固定分数段发证，纸质证书另行付费，因此不应与中大官方校赛或学会赛事同权推荐。[经开杯项目赛通知](https://www.cxcyds.org.cn/401.html)、[双创能力赛通知](https://www.cxcyds.org.cn/30.html)

逐条结论见：`data/competitions/quality_review_2026-08-11.csv`。

## 4. 组队语义

24 条赛事中：

- **17 条**允许正式团队参赛，`team_forming_supported=true`，客户端主按钮显示“组队”；
- **7 条**为个人赛，`team_forming_supported=false`，客户端显示“找备赛搭子”；
- 允许单人或团队参赛的赛事，创建组队意图时最低成局人数强制为2，不再生成1人局；
- 个人赛编译为 `比赛备赛搭子 + similar`，默认3人，不把备赛关系误写成官方参赛队。

服务端输出：

```json
{
  "participation_mode": "individual_or_team",
  "team_forming_supported": true,
  "collaboration_action": "official_team",
  "registration_mode": "school_notice",
  "registration_instructions": "按中山大学校内通知完成材料与报名",
  "fee_note": "报名费300元/队",
  "recommendation_tier": "A",
  "verified_at": "2026-08-11T20:27:06+08:00"
}
```

报名动作枚举：

| `registration_mode` | 前端行为 |
|---|---|
| `direct` | 展示“去官网报名”，直接打开 `registration_url` |
| `school_notice` | 展示“查看校内报名步骤”，同时呈现操作说明 |
| `school_coordinated` | 展示“联系校内负责人”，不得暗示学生可直接完成报名 |

## 5. 数据库变更

迁移 `20260811_0003` 为 `competition_events` 增加：

```text
participation_mode
registration_mode
registration_instructions
fee_note
recommendation_tier
verified_at
```

API 新增：

```text
GET /competitions?team_only=true
GET /competitions?recommendation_tier=A
```

公开查询会实时排除已经过报名截止的条目；每日 Celery 任务按 `registration_deadline` 下架。即使作品提交截止仍在未来，报名已经结束的赛事也不会继续作为“可报名赛事”展示。

## 6. 服务器入库

先校验文件：

```bash
cd /path/to/compusone
sha256sum -c fixtures/competition_snapshot_2026-08-11_v1.1.sha256
uv run python scripts/validate_competition_snapshot.py \
  fixtures/competition_snapshot_2026-08-11_v1.1.json
```

再迁移并幂等导入：

```bash
uv run alembic upgrade head
uv run onemore-ingest-competitions \
  fixtures/competition_snapshot_2026-08-11_v1.1.json
```

也可使用：

```bash
make competitions-ingest
```

摄取 CLI 会先补齐参考能力标签，再在单个事务内完成24条 upsert；任一未知能力映射会整批回滚。

PostgreSQL 验收 SQL：

```sql
SELECT snapshot_version, count(*)
FROM competition_events
WHERE snapshot_version = 'competition-radar-cn-v1.1-2026-08-11'
GROUP BY snapshot_version;

SELECT recommendation_tier, count(*)
FROM competition_events
WHERE snapshot_version = 'competition-radar-cn-v1.1-2026-08-11'
GROUP BY recommendation_tier
ORDER BY recommendation_tier;

SELECT count(*)
FROM competition_events e
JOIN competition_constraints c ON c.competition_id = e.id
WHERE e.snapshot_version = 'competition-radar-cn-v1.1-2026-08-11'
  AND c.team_size_max > 1;
```

预期分别为：总数24；A/B/C 为14/6/4；可正式组队17。
