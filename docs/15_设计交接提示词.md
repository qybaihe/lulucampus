## 一、这是什么产品

中山大学校园里的「成局」工具。学生说一句想做的事——想找人组队打比赛、想凑人打球、
想约研讨室赶 DDL——App 负责把缺的人凑齐，并真的去把场地订下来、写进日历，然后退场。

**一句话定位：AI 不介绍人，AI 促成事。**

三个必须被设计传达出来的产品性格：

1. **最小单元是「一个局」，不是「一个人」。** 这不是交友软件。没有人物卡片流、没有刷人、
   没有个人主页、没有加好友。用户看到的永远是「这件事还差什么」，不是「这个人怎么样」。
2. **AI 越早退场越好。** 名叫 Lulu 的水豚负责把事促成，人凑齐、场订好之后它就走开，
   剩下的交给真人自己聊。它不是陪伴型 AI，不养成、不闲聊、不刷存在感。
3. **凑不齐就安静地结束。** 失败不归因给任何人，没有「谁拒绝了你」，没有人知道你开过口。

**用户**：中山大学本科生与研究生，多校区（东校园 / 南校园 / 北校园 / 珠海）。

**平台**：iOS 原生 App。请按 iPhone 现役主力尺寸出图，并说明 Dynamic Type 放大后的处理思路。

## 二、导航结构

底部五入口固定：

```
今天    比赛    ⊕ 差一个（中央主动作）    消息    我
```

- **今天** — 默认落地页。今日日程 + 待办 + 校园工具入口。
- **比赛** — 已核验、可报名的赛事，以及每个赛事的组队缺口。
- **⊕ 差一个** — 全局主动作。说出想做的事，从这里发起一个局。
- **消息** — 只有已成局的人才会出现在这里。没有陌生人私聊。
- **我** — 个人画像、信任等级、授权与隐私设置。

二级入口：`公开局`、`我的局`、`搭子关系` 从「今天」进入；个人设置从「我」进入。

## 四、视觉方向（轻引导，其余由你决定）

### 4.1 IP 形象：水豚 Lulu

已有成品素材，直接使用，不需要重新设计角色：

- **10 个状态动画**，每个为 4 帧循环：待机、在听、在想、回应、关切、庆祝、
  举意图卡、等待招募、清点确认、递出预约单、正在执行、**退场**
- 每帧已做口鼻与脚底双锚点对齐，切帧时角色不位移
- 透明 PNG，1254×1254 精灵表 + 已切好的单帧

**出场原则**：Lulu 是主元素，贯穿各功能，营造陪伴感。
但**只在有事发生时出现**——在听、在想、办成了、出问题了、要走了。
不做等级成长、不做喂养、不做签到、不主动搭话。**事情办完就退场。**

参考尺寸（可调整）：主场景 240–300pt，页面头部 96–140pt，
空态/错误态 140–190pt，确认卡 72–96pt，消息头像 36–48pt。

### 4.2 图标素材：白边贴纸

已有 36 张成品贴纸，半写实手绘卡通、统一光照、每个主体带连续白色切边，512×512 透明 PNG：

| 组 | 内容 |
|---|---|
| 桌与座 | 空椅子、圆桌、空白名牌、门禁卡、二维码牌、沙漏 |
| 运动 | 羽毛球拍与球、篮球、乒乓球拍与球、足球、跑鞋、水壶 |
| 学业 | 书堆、笔记本电脑、活页本、马克笔、闹钟、台历 |
| 校园 | 研讨室门牌、台灯、教学楼、校车、空白海报、餐盘 |
| 能力角色 | 服务器（后端）、浏览器窗（前端）、柱状图（数据）、便利贴（产品）、齿轮（算法）、调色板（设计） |
| 成果状态 | 奖杯、证书、徽章、信封、对话气泡、对勾印章 |

**需要新素材时，请沿用同一风格**：半写实手绘卡通、统一光照、约主体宽度 5% 的连续白边、
表面留白不写字。

### 4.3 整体气质

亮色、暖调、有呼吸感——接近生活方式类 App 的观感，不是工具类的冷灰，
也不是深色霓虹科技风。产品讲的是「低刺激、办完就走」，视觉不该喊。

一个参考色向（**可以改，只是起点**）：暖纸底、深墨绿黑文字、一个明黄作为唯一强调色，
配灰绿中性色。之所以是单强调色，是因为界面里最需要被一眼看到的东西只有一个：**缺口**。

**唯一一条硬性的颜色语义要求**：
「已具备 / 已就位」和「缺口 / 还差一个」必须是两种明确不同的视觉状态，
且「缺口」是全屏视觉权重最高的元素。
**不要用红色表达缺口**——红会被读成「错误」，而缺口是邀请。

### 4.4 明确不规定的部分

以下全部由你决定，本文档不做要求：栅格与间距体系、圆角、卡片样式、按钮层级与形态、
字体选择与字号阶梯、图标线性/面性、阴影、动效曲线与时长、深色模式是否做、
列表与详情的具体布局、空态插画构图。

## 五、产品红线（不可协商）

以下内容在**任何**页面、卡片、浮层、通知、空态、异常态中都不得出现。
这些不是审美偏好，是产品定义——出现即为设计错误：

1. 他人的信任等级、等级标识、积分或排行榜
2. 他人的原始课表、具体忙碌原因或个人时间信息
3. 同课同学名单
4. 「某某拒绝了你」或任何把失败归因给个人的文案
5. 招募未满员时的报名人数、报名者或报名情况
6. 实时在场者、实时位置、当前谁在图书馆/健身房
7. 无限人物卡片流、刷人入口
8. 朋友圈式动态流、公开个人主页
9. 双向确认前的真实身份
10. 成绩、绩点或学业表现
11. 图书馆自习区、健身房器械区的现场社交入口
12. 加好友、好友申请、陌生人搜索、通讯录扩列
13. 已读回执、在线状态、正在输入
14. 共同经历里的评价、印象、性格或可靠性标签
15. 搭子数量排行、最常一起的人等跨关系聚合
16. 基于记忆的主动召回与关系回顾
17. AI 主动闲聊、人格养成或维持活跃度的机制
18. 招募期群聊、陌生人私聊、拉人进群、群二维码
19. 跳过预览直接预约的入口
20. 请假、选课、成绩、支付、简历投递、岗位申请、勤工助学、离返校登记的代理执行入口

**红线 1/5/6/7/8/9/12/13/15 的共同后果**：一般社交产品用来填满页面的东西
（头像墙、在线状态、动态流、人数热度）在这里全部不能用。
页面显得空的时候，**不要用这些东西补**。请用信息结构本身去承担视觉重量。
