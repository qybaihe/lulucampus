## 5. 数据更新方法

1. 以 `Asia/Shanghai` 为核验时区，记录核验时间为 ISO 8601：`YYYY-MM-DDTHH:MM:SS+08:00`。
2. 优先打开赛事官网、主办方官网、教育主管部门或学校官方通知；同一赛事合并来源，优先保留赛项通知和学校当前报名通知。
3. 只有同时具备中文正式名称、官方来源 URL、官方报名 URL、有效截止时间、资格/队伍人数和可解释的模式/地点/奖励，才进入快照并标记 `可行动`。
4. 报名已截止、官方日期存在冲突、报名入口已关闭或队伍/奖励字段缺失的项目写入 `leads_2026-08-11.json`，并在 CSV 的“缺失字段”列说明原因。
5. `external_key` 使用赛事和赛道的稳定英文/拼音标识；同一赛事不同来源不生成随机 ID。
6. `required_skills` 只使用后端能力空间中的九个 key：`backend`、`frontend`、`machine_learning`、`data_analysis`、`product`、`visual_design`、`design`、`business_analysis`、`operations`。
7. 新一批数据先复制为新的日期版本，再执行 Pydantic 校验、external_key/URL/时间/队伍约束检查、临时 SQLite 导入和 competitions 测试；不覆盖旧快照或演示 fixture。

## 6. 服务端导入命令

在项目根目录执行：

```bash
make competitions-ingest
```

该命令先校验并导入 `fixtures/competition_snapshot_2026-08-11_v1.1.json`，调用 `onemore.modules.competitions.service.ingest_snapshot_path`：只接受 `可行动` 条目，映射到能力标签后写入 `CompetitionEvent`、`CompetitionSkill` 和 `CompetitionConstraint`。不要导入 `data/competitions/leads_2026-08-11.json`，也不要用本文件覆盖 `fixtures/competition_snapshot.json`。
