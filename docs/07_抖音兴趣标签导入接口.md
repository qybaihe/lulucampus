# 差一个 · ONE MORE：抖音兴趣标签导入接口（黑客松 MVP）

## 1. 目标

在 ONE MORE 中增加一个独立的「抖音兴趣画像导入」能力：

1. 用户点击开始导入。
2. 后端启动隔离的 Chrome / Playwright 会话。
3. App 展示抖音登录二维码；用户使用抖音扫码确认（新设备可能再要求手机号验证）。
4. 后端自动识别当前登录账号并采集该账号的喜欢作品。
5. 后端基于内容立即生成可用画像（主标签、副标签、领域、维度、摘要、置信度），状态直接进入 `READY`，`calibrated=false`。
6. 可选：用户回答 3–5 道**领域细化题**，只细化子兴趣与表达方式，覆盖画像并标记 `calibrated=true`。

本方案不接入抖音开放平台，不使用 ClientKey、ClientSecret、OAuth 应用审核或上架能力，直接复用已经验证过的网页登录二维码与喜欢列表采集方式。

## 2. 产品边界

- 标签默认私有，只给本人和 ONE MORE 的匹配/成局理由使用。
- 不把喜欢列表做成公开动态、社交主页或用户搜索条件。
- 抖音推断的兴趣标签与课程产生的 `verified_tags` 分开保存，不写入已验证能力。
- 浏览器登录 Cookie 只存在于导入任务的隔离运行目录中；采集结束、取消或失败后清理。
- 客户端不接收 Cookie、签名参数或原始浏览器状态。

## 3. 总体链路

```mermaid
flowchart LR
    A["POST 创建导入任务"] --> B["PREPARING_QR"]
    B --> C["WAITING_SCAN"]
    C --> D["用户抖音扫码"]
    D --> E["AUTHENTICATED"]
    E --> F["RESOLVING_PROFILE"]
    F --> G["COLLECTING"]
    G --> H["ANALYZING"]
    H --> I["READY calibrated=false"]
    I --> J["可选 3–5 道领域细化题"]
    J --> K["READY calibrated=true"]
```

客户端采用轮询，不额外引入 WebSocket/SSE：创建接口返回 `poll` 和 `poll_after_seconds=2`。

## 4. 状态机

| 状态 | 含义 | 可执行动作 |
|---|---|---|
| `PREPARING_QR` | 正在启动浏览器并打开登录页 | 查询、取消 |
| `WAITING_SCAN` | 二维码可展示，等待扫码 | 查询、刷新二维码、取消 |
| `QR_SCANNED` | 抖音 App 已扫码，等待确认后进入手机号验证 | 查询、取消 |
| `PHONE_REQUIRED` | 二维码已确认，抖音要求手机号验证 | 请求短信验证码、查询、取消 |
| `WAITING_SMS_CODE` | 短信验证码已发送 | 提交验证码、查询、取消 |
| `AUTHENTICATED` | 已捕获登录态 | 查询、取消 |
| `RESOLVING_PROFILE` | 正在识别当前账号与个人页 | 查询、取消 |
| `COLLECTING` | 正在分页采集喜欢内容 | 查询、取消 |
| `ANALYZING` | 正在生成内容画像与可选细化题 | 查询 |
| `READY` | 画像已可用；可选答题细化 | 查询结果/问题、提交答案、重新导入 |
| `NEEDS_CONFIRMATION` | （遗留）旧流程等待答题；新链路不再进入 | 查询问题、提交答案 |
| `QR_EXPIRED` | 二维码过期 | 刷新二维码、取消 |
| `FAILED` | 任务失败 | 查询错误、重新创建 |
| `CANCELLED` | 用户取消并完成清理 | 重新创建 |

服务端任务必须检查取消状态；浏览器等待与每次滚动后都要检查一次。

## 6. 接口定义

### 6.1 创建抖音导入任务

```http
POST /profile/imports/douyin
```

请求：

```json
{
  "profile_url": null,
  "max_items": 0,
  "force": false
}
```

字段：

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---:|---|
| `profile_url` | `string|null` | `null` | 正常无需填写；账号自动识别失败时可用个人主页分享链接兜底 |
| `max_items` | `integer` | `0` | `0` 表示采集到 `has_more=0`；演示时可设置上限 |
| `force` | `boolean` | `false` | 是否取消当前未完成任务并重新开始 |

返回 `202 Accepted`：

```json
{
  "data": {
    "id": "imp_01J...",
    "source": "douyin",
    "status": "PREPARING_QR",
    "qr_image_data_url": null,
    "qr_version": 0,
    "qr_expires_at": null,
    "expires_at": "2026-08-11T20:30:00Z",
    "source_profile": null,
    "progress": {
      "phase": "preparing_qr",
      "current": 0,
      "total": null,
      "percent": null,
      "message": "正在打开抖音登录页"
    },
    "collection": null,
    "candidate_tags": [],
    "question_count": 0,
    "result": null,
    "error": null
  },
  "meta": {
    "login_methods": ["qr_then_phone"],
    "qr": "/profile/imports/imp_01J.../qr",
    "phone_code": "/profile/imports/imp_01J.../phone/code",
    "verify": "/profile/imports/imp_01J.../verify",
    "poll": "/profile/imports/imp_01J...",
    "poll_after_seconds": 2
  }
}
```

同一用户同时只允许一个非终态导入任务。没有 `force` 时返回当前任务；`force=true` 时先取消和清理旧任务，再创建新任务。

### 6.3 刷新过期二维码

```http
POST /profile/imports/{import_id}/qr/refresh
```

请求体为空。仅 `WAITING_SCAN`、`QR_EXPIRED` 状态允许调用；操作幂等。

返回 `202 Accepted`，状态回到 `PREPARING_QR`，`qr_version` 在新二维码产生后加一。客户端发现 `qr_expires_at` 到期后可自动刷新一次，同时保留“二维码过期，点击刷新”按钮。

### 6.4 取消任务

```http
POST /profile/imports/{import_id}/cancel
```

行为：

- 状态改为 `CANCELLED`。
- 终止对应浏览器进程/Context。
- 删除任务运行目录、Cookie 和未使用的原始数据。
- 重复调用仍返回 `CANCELLED`。

### 6.5 串行登录：二维码 → 手机号验证

客户端不打开浏览器，不接收 Cookie。浏览器只作为服务端 `headless` 隔离执行引擎。

1. 获取纯二维码：

```http
POST /profile/imports/douyin/qr?wait_seconds=10
GET /profile/imports/{import_id}/qr
GET /profile/imports/{import_id}/qr/image
```

`qr/image` 直接返回 `image/png`，用于 `<img>` / SwiftUI `AsyncImage`；JSON 接口也保留 `qr_image_data_url`。

2. 轮询扫码与登录阶段：

```http
POST /profile/imports/{import_id}/verify?wait_seconds=15
```

扫码后依次返回 `QR_SCANNED`、`PHONE_REQUIRED`。手机号验证完成前 `verified=false`。

3. 请求短信验证码（仅 `QR_SCANNED` / `PHONE_REQUIRED` 可调用）：

```http
POST /profile/imports/{import_id}/phone/code
Content-Type: application/json

{"phone":"13800138000","country_code":"86"}
```

返回只包含 `phone_masked=138****8000`，原始手机号不落库、不写日志、不进入 API 响应。

4. 提交短信验证码：

```http
POST /profile/imports/{import_id}/phone/verify
Content-Type: application/json

{"code":"123456"}
```

验证码仅在线程内存中传给隔离浏览器 Context，处理后立即覆盖，不落库、不写日志。捕获 `sessionid/sessionid_ss/sid_tt/sid_guard` 后记录不含凭证值的 `authenticated_at`，状态进入 `AUTHENTICATED` 并自动继续账号解析与喜欢列表采集。

5. 查询手机号验证状态：

```http
GET /profile/imports/{import_id}/phone
```

只返回脱敏手机号、`code_sent`、`verified` 与 `authenticated_at`。

### 6.9 获取我的兴趣标签

```http
GET /profile/taste/me
```

没有完成画像时返回 `data: null`；采集分析完成后即可返回可用画像（`calibrated` 表示是否完成可选细化）。

返回体与 6.8 的 `TasteProfileResultView` 同构，额外可能包含：

- `persona`：AI 生成的人物气质长文案  
- `matching_hints`：匹配/成局短提示  
- `sample.generation`：`llm` 或 `rule`  
- `sample.llm_model`：固定 `deepseek-v4-flash`（AI 成功时）

同时为现有 `GET /profile/me` 增加一个向后兼容的可选字段：

```json
{
  "taste_profile": {
    "primary_tag": {"key": "explorer_builder", "label": "探索型 Builder"},
    "secondary_tags": ["AI 实践派", "务实浪漫"],
    "summary": "...",
    "confidence": 0.86
  }
}
```

不要把这些标签写入 `verified_tags`。

### 6.10 仅刷新 AI 文案（不重新扫码）

```http
POST /profile/taste/me/ai-refresh
```

复用最近一次 `READY` 导入的本地喜欢列表，调用 OpenCode Go · DeepSeek V4 Flash 重写 `summary` / `persona` / `interest_facets` / `matching_hints`。  
标签分数仍由内容基线决定。Flash 失败时降级规则文案，任务保持 `READY`。

`meta` 示例：

```json
{
  "llm_provider": "opencode-go",
  "llm_model": "deepseek-v4-flash",
  "endpoint": "https://opencode.ai/zen/go/v1/chat/completions"
}
```

### 6.11 删除抖音画像

```http
DELETE /profile/taste/me/douyin
```

删除抖音导入产生的画像、题目答案、规范化喜欢条目和相关任务产物；不影响课程能力、身份、课表与其他模块。

## 7. 数据模型

### 7.1 `TasteImportSession`

建议表名：`taste_import_sessions`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string PK | 导入任务 ID |
| `user_id` | FK users | 所有者 |
| `source` | string | 固定 `douyin` |
| `status` | string/index | 状态机 |
| `profile_url` | text nullable | 可选兜底链接 |
| `qr_image_data_url` | text nullable | 当前二维码 |
| `qr_version` | int | 二维码版本 |
| `qr_expires_at` | datetime nullable | 二维码过期时间 |
| `expires_at` | datetime | 整个任务过期时间 |
| `source_profile` | JSON | 昵称、头像、uid、sec_uid |
| `progress` | JSON | phase/current/total/message |
| `collection_summary` | JSON | 页数、条数、has_more 等 |
| `candidate_tags` | JSON | 初始候选标签 |
| `questions` | JSON | 3–5 道题，不含前端不需要的内部权重 |
| `answers` | JSON | 用户答案 |
| `analysis_snapshot` | JSON | 主题/维度聚合，不含 Cookie |
| `result_snapshot` | JSON | 最终标签结果 |
| `raw_artifact_path` | text nullable | 仅服务端调试使用，禁止出现在响应中 |
| `error_code` | string nullable | 稳定错误码 |
| `error_message` | text nullable | 用户可读信息 |
| `created_at/updated_at/completed_at` | datetime | 时间字段 |

### 7.2 `TasteProfile`

建议表名：`taste_profiles`

| 字段 | 类型 | 说明 |
|---|---|---|
| `user_id` | FK users / PK | 当前用户 |
| `source` | string | `douyin` |
| `source_import_id` | FK | 最近一次完成导入 |
| `primary_tag` | JSON | 主标签 |
| `secondary_tags` | JSON | 副标签 |
| `interest_domains` | JSON | 兴趣领域 |
| `dimensions` | JSON | 行为维度 |
| `summary` | text | 一句话画像 |
| `confidence` | float | 0–1 |
| `sample_summary` | JSON | 样本统计 |
| `model_version` | string | `taste-v2` |
| `confirmed_at` | datetime | 回答完成时间 |
| `created_at/updated_at` | datetime | 时间字段 |

规范化喜欢条目可放在 `TasteImportItem` 表，也可在黑客松 MVP 中存为任务目录下 JSONL，并由分页接口读取。为了避免 2,000+ 行数据污染核心数据库，MVP 推荐 JSONL + 数据库只存聚合结果。

## 8. 浏览器采集器契约

建议目录：

```text
onemore/modules/taste_profile/
  api.py
  schemas.py
  service.py
  analyzer.py
  taxonomy.py
  orchestrator.py
  providers/
    base.py
    fake.py
    douyin_browser.py
```

`DouyinBrowserProvider` 必须完成：

1. 为每个 `import_id` 创建独立目录：`runtime/douyin/{import_id}/`。
2. 使用随机空闲 CDP 端口或 Playwright persistent context，禁止所有用户共用固定 `9223`。
3. 打开抖音网页并触发登录弹窗。
4. 截取登录二维码元素，写入 `qr_image_data_url`。
5. 轮询 Cookie，出现 `sessionid`、`sessionid_ss`、`sid_tt`、`sid_guard` 任一登录态标志后进入 `AUTHENTICATED`。
6. 自动获取当前账号 `sec_uid`：优先读取当前用户接口/页面状态，其次解析登录后头像对应的 `/user/{sec_uid}` 链接；若仍失败且创建请求提供 `profile_url`，使用该链接兜底。
7. 打开 `https://www.douyin.com/user/{sec_uid}?showTab=like`。
8. 监听包含 `/aweme/v1/web/aweme/favorite/` 的响应。
9. 用 `aweme_id` 去重；接口返回的 `aweme_list` 是权威数据，不能把 DOM 中推荐位、侧栏链接混入喜欢列表。
10. 滚动页面中最大的可滚动容器，直到捕获 `has_more=0`；同时设置稳定轮次与总超时兜底。
11. 每得到一页就更新 `api_pages`、`items_collected` 与状态消息。
12. 规范化字段后交给分析器。
13. 成功、失败、超时、取消都必须关闭 Context/Chrome 并清理 Cookie 与运行目录。

## 9. 标签与选择题算法

### 9.1 内容基线

从作品标题、描述、话题标签、平台分类和作者昵称构造文本，计算：

- 兴趣领域：AI/编程/开源、科技/数码、游戏/策略、摄影/影像、音乐/文学、旅行/城市、成长/职业、健康/运动、关系/家庭、幽默/萌宠、财经/消费、知识/方法论。
- 行为信号：行动导向、低成本优化、审美导向、竞争成就、轻松娱乐。
- 广度信号：唯一作者数、单次作者比例、头部作者集中度。
- 最近重心：喜欢列表前 200 条作为近期窗口；接口没有精确点赞时间，不把作品发布时间当作点赞时间。

### 9.2 候选标签

MVP 至少支持：

| key | 标签 |
|---|---|
| `explorer_builder` | 探索型 Builder |
| `ai_practitioner` | AI 实践派 |
| `practical_romantic` | 务实浪漫 |
| `strategic_player` | 策略玩家 |
| `knowledge_curator` | 知识策展人 |
| `aesthetic_observer` | 审美观察者 |
| `growth_driver` | 成长驱动者 |

### 9.3 问题选择

- 从分数接近或置信度最低的维度中挑题。
- 最少 3 题，最多 5 题。
- 固定题库即可，不依赖外部模型。
- 题目只问动机和行为，不重复问“你是否喜欢 AI/摄影”这类已从内容得出的事实。

### 9.4 校准公式

```text
content_weight = 样本 >= 200 时 0.70，否则 0.50
quiz_weight = 1 - content_weight
final_score[tag] = content_score[tag] * content_weight
                 + quiz_score[tag] * quiz_weight
```

主标签取最高分；副标签取不同维度的 2–3 个高分标签。`confidence` 可由样本充分度、第一/第二名差值和题目回答一致性共同计算。

## 11. 后台执行

浏览器任务可能持续数分钟，接口不能同步阻塞。

- 本地黑客松模式：使用一个进程内 `ThreadPoolExecutor(max_workers=2)` 或专用后台线程池；每个任务内部自己创建 `SessionLocal()`。
- 保留未来 Celery 接口，但 MVP 不要求 Redis/Celery 才能跑。
- 参考现有 `onemore/hermes/login.py` 的长任务、二维码发布、取消检查和终态持久化写法。
- 进程重启后，启动时把非终态导入任务标记为 `FAILED`，错误码 `IMPORT_WORKER_RESTARTED`，不要让任务永久卡住。

## 12. 稳定错误码

| 错误码 | 场景 |
|---|---|
| `DOUYIN_IMPORT_DISABLED` | 功能未开启 |
| `DOUYIN_BROWSER_UNAVAILABLE` | Chrome/Playwright 不可用 |
| `DOUYIN_QR_NOT_FOUND` | 登录页未找到二维码 |
| `DOUYIN_QR_EXPIRED` | 二维码过期 |
| `DOUYIN_LOGIN_TIMEOUT` | 长时间未扫码 |
| `DOUYIN_PROFILE_NOT_FOUND` | 登录后仍无法识别当前账号 |
| `DOUYIN_LIKES_UNAVAILABLE` | 喜欢页不可访问或为空 |
| `DOUYIN_RATE_LIMITED` | 页面/接口触发频率限制 |
| `DOUYIN_COLLECTION_STALLED` | 多轮滚动没有新数据且未到末页 |
| `DOUYIN_COLLECTION_TIMEOUT` | 采集超过总时限 |
| `IMPORT_INVALID_STATE` | 当前状态不允许该动作 |
| `INVALID_QUIZ_ANSWER` | 问题或选项不存在 |
| `IMPORT_WORKER_RESTARTED` | 后台任务随进程重启中断 |

后台失败写入任务 `error_code/error_message`；轮询接口仍返回任务对象，客户端根据 `status=FAILED` 展示重试按钮。请求本身的权限/参数错误使用正常 HTTP 4xx。
