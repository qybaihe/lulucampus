# 02 · 后端服务开发指南

> 对应 V2.1 产品方案
> 服务代号：`onemore-server`（业务服务 · 阿凑）
> 行动代理 `onemore-hermes` 见《03_行动代理与Hermes设计》

**本文说明每个模块该有什么能力、对外什么契约、受什么约束。具体算法实现不在本文范围。**

---

## 1. 服务边界

### 1.1 后端承担什么

**全部业务逻辑。** 匹配、成局判定、信任计算、共同经历沉淀、定时任务、隐私强制。

### 1.2 三条硬边界

| 边界 | 含义 |
|---|---|
| **不持有校园凭证** | 凭证在 hermes 的 Vault 里，业务服务只能调 Action Schema |
| **不下发原始日程** | 对外只输出交集，永不输出任何人的课表（F8 F24-4） |
| **不下发他人等级** | 等级只用于匹配侧分层与解锁校验（F17） |

> 这三条不是靠代码规范保证，是靠**接口设计上根本没有返回这些数据的字段**保证。

---

## 2. 服务拓扑

```
                  ┌──────────────┐
   iOS App ──────▶│ onemore-server│──────▶ PostgreSQL
                  │    (阿凑)     │──────▶ Redis
                  └───────┬──────┘
                          │ Action Schema（唯一出口）
                          ▼
                  ┌──────────────┐
                  │ onemore-hermes│──────▶ 校园系统
                  └──────────────┘
```

**技术选型**

| 项 | 选型 | 说明 |
|---|---|---|
| 框架 | Python + FastAPI | 组合优化生态更顺 |
| 主库 | PostgreSQL | 事务性强，成局状态机依赖它 |
| 缓存/锁 | Redis | 匹配池、成局并发锁、限流 |
| 任务队列 | Celery | 成局判定、超时、提醒、巡检 |
| 实时通道 | WebSocket | 群聊、局状态推送 |
| LLM | 仅意图编译 + 理由生成 | **不参与匹配打分，不参与执行** |

## 3. 模块职责

### 3.1 `identity/` 身份与授权

**职责**：扫码认证编排、身份事实、授权范围管理。

| 能力 | 说明 |
|---|---|
| `create_login_session(user_id)` | 创建异步登录会话，返回 session_id |
| `get_login_session(session_id)` | 轮询状态：PENDING / WAITING_SCAN / SUCCESS / TIMEOUT / FAILED |
| `get_identity_facts(user_id)` | 学院、专业、年级、校区——**只读，无 setter** |
| `grant(user_id, scope)` / `revoke(user_id, scope)` | 分项授权与撤回 |
| `cascade_purge(user_id, scope)` | 撤回后清除派生数据 |

**约束**
- 认证事实字段**没有写接口**，从架构上杜绝用户编辑（F1）
- 撤回课表授权 → 必须级联清除课表缓存、空档索引，并将用户移出依赖时间的匹配池
- 登录是长任务，**不可在 HTTP 请求内同步等待**（见 03 文 7.1）

---

### 3.2 `profile/` 画像

**职责**：培养方案解析、课程映射、能力向量、跨专业信号。

| 能力 | 说明 |
|---|---|
| `init_profile(user_id)` | 全量初始化，A5 页面的后端 |
| `map_course_to_domain(course_code)` | 课程 → 学科域 + 能力标签 |
| `build_capability_vector(user_id)` | 能力向量，区分已验证/自述权重 |
| `compute_cross_major_score(user_id)` | F3 跨专业主动性得分 |
| `edit_self_reported_tags(user_id, tags)` | 只能改自述标签 |

**关键规则**
- **只使用"修过什么"，不使用"修得怎么样"**——成绩字段在数据模型里**不存在**（F2）
- 已验证标签可隐藏，**不可伪造**
- 自述标签权重显著低于已验证标签

**课程映射表的维护**
- 首版：规则 + LLM 批量标注，人工校验高频课程
- 这是一次性重投入、长期低成本的资产，值得前期做扎实
- 需要培养方案的**必修集合**作为 F3 判定基准，务必抓全

---

### 3.3 `schedule/` 课表与空档

**职责**：课表 ETL、空档计算、校区通勤矩阵。

| 能力 | 说明 |
|---|---|
| `etl_term_timetable(user_id)` | 全学期一次性扫描并落库（决议六） |
| `weekly_delta_check(user_id)` | 每周增量校验调课/补课 |
| `get_free_windows(user_id)` | 单人可用窗口——**仅返回给本人** |
| `intersect_windows(user_ids)` | 多人交集，F8 核心 |
| `is_reachable(campus_a, campus_b, gap)` | 跨校区通勤可行性 |
| `stability_score(user_id, window)` | 空档稳定性——长期搭子匹配的关键变量 |

**约束（F8，最重要的隐私强制点）**
- `intersect_windows` **只返回交集与可行人数，不返回任何个人归属信息**
- 返回结构里**没有** `user_id` 字段，从类型上杜绝泄漏
- 与场地可用性联合计算，避免推荐"人有空但没场"

### 3.4 `intent/` 意图

**职责**：意图编译、意图卡 schema、匿名意图池。

| 能力 | 说明 |
|---|---|
| `compile(text, user_context)` | LLM 编译，**输出必须过严格 schema 校验** |
| `prefill(user_id)` | 用 F2/F3 预填能力、用 F8 预填时间 |
| `publish(card)` | 进入匿名池 |
| `withdraw(card_id)` | 撤回 |
| `expire_sweep()` | 定时清理过期意图 |

**约束**
- LLM 输出**不接受自由文本**，必须是强类型 schema，校验失败则走澄清（D2）
- 澄清**最多两轮**，之后用默认值出草稿
- **记录用户修改了哪些字段**——这是意图编译准确率的核心指标

---

### 3.5 `matching/` 匹配

**职责**：搭子相似匹配、组队组合优化、理由生成。

| 能力 | 说明 |
|---|---|
| `match_similar(pool, constraints)` | 模式一：求相似（F7） |
| `match_complementary(pool, constraints)` | 模式二：求互补，组合优化（F7） |
| `generate_reason(gathering)` | LLM 生成"为什么是你们" |

**模式一 · 搭子（求相似）**
加权打分，时间重合度权重最高（30%）。所有搭子产品死在"兴趣对得上、时间对不上"，而我们有真实课表。

**模式二 · 组队（求互补）**
组合优化，**不是两两推荐**。目标：在目标一致的约束下找能力差异最大的组合。

约束项：人数、必需角色全覆盖、共同时间下限、校区可达、全员 ≥ T2。

**实现建议**
- 首版贪心 + 局部搜索足够；池子大了再上更好的求解器
- **不要用 LLM 做匹配打分**——不可复现、不可解释、不可调优

**共同经历加权** `[V2.1]`
有共同经历的候选人显著加权（F18：复局是最强正信号）。这使匹配随时间自我强化——**这是 Day 100 壁垒的机制**。

### 3.6 `gathering/` 成局

**职责**：状态机、多人确认、补位、容错。**这是全系统最需要正确性的模块。**

**状态机**

| 状态 | 进入条件 | 出口 |
|---|---|---|
| `Draft` | 意图草稿 | → Pooling |
| `Pooling` | 已发布，匿名招募 | → Tentative / 静默解散 |
| `Tentative` | 达到最低人数 | → Confirmed / 回 Pooling |
| `Confirmed` | 全员分别确认 | → Previewed |
| `Previewed` | 行动预览已生成 | → Executed / 回 Confirmed |
| `Executed` | 预约真实成功 | → Active |
| `Active` | 局进行中 | → Completed |
| `Completed` | 完成 | → Recurred / Archived |

**并发与幂等（必须做对）**
- 成局判定是定时任务，需**幂等 + 分布式锁**
- **同一用户不能被同时锁进两个时间冲突的局**——用户级锁 + 时间冲突校验
- 状态转移全部走单一入口 `transition(gathering_id, event)`，禁止散落各处直接改状态

**静默解散（F9）**
- 不发失败通知，或只发极弱中性通知
- **数据层面也不保留"谁报名过"的可查询视图**——不是靠前端不显示，是靠后端查不到

**异常分支**

| 分支 | 处理 |
|---|---|
| 人数不足 | 静默解散，意图可顺延至相邻时段 |
| 成员拒绝 | 回候选池，**不记录也不暴露拒绝者** |
| 场地失效 | 重算时段，重走预览 |
| 临时退出 | 触发补位 |
| 举报 | 永久切断双方匹配链路 |

### 3.7 `trust/` 信任

**职责**：信任事件、等级计算、升降级、解锁校验。

| 能力 | 说明 |
|---|---|
| `record_event(user_id, type, ref)` | 写入信任事件 |
| `recompute_level(user_id)` | 重算等级 |
| `check_unlock(user_id, capability)` | **解锁校验——所有受限能力的统一入口** |
| `get_progress(user_id)` | 距下一级差什么（仅本人） |
| `enter_observation(user_id)` / `restore(user_id)` | 降级观察期与恢复 |

**事件权重**

| 事件 | 影响 |
|---|---|
| 按时确认 | + |
| 提前 ≥24h 取消 | **中性——不惩罚合理取消** |
| 临期 <2h 退出 | − − |
| 确认后未出现 | − − − |
| 预约执行成功 | + |
| 局后完成确认 | + |
| **与原成员复局** | **+ +（最强正信号）** |
| 有效举报 | 立即降至 T1 |

**约束**
- **`get_progress` 只接受本人调用**，无"查他人等级"的接口存在（F17）
- 升降级全自动，无审批流
- 降级必须**通知本人 + 说明原因 + 提供申诉入口**，且**不产生任何公开标记**
- 不存在排行榜相关的任何查询能力

### 3.8 `collab/` 协作与对话 `[V2.1 大幅扩展]`

**职责**：协作空间、人际对话、共同经历账本、退场协议、目标追踪。

#### 3.8.1 协作空间

| 能力 | 说明 |
|---|---|
| `create_space(gathering_id)` | 成局后生成 |
| `generate_opener(gathering_id)` | AI 开场信息（基于真实共同点） |
| `archive_space(gathering_id)` | 归档，**对话与账本保留** |

#### 3.8.2 人际对话（F28）

| 能力 | 说明 |
|---|---|
| `open_channel(gathering_id)` | **仅在 Confirmed 之后开启**，招募期不可用 |
| `send_message(channel_id, user_id, content)` | 发消息 |
| `mention_azou(channel_id, text)` | @阿凑触发工具调用，用完即退 |
| `close_channel(relation_id, by_user)` | 单方面解除 |

**约束（逐条对应 F28）**
- **不存在** `search_user`、`add_friend`、`send_request` 类接口——**关系只能由成局产生**
- **不实现**已读回执、在线状态、正在输入
- 解除关系后通道关闭，**对方不产生任何通知或事件**
- 消息推送需合并与限频

#### 3.8.3 共同经历账本（F29）

| 能力 | 说明 |
|---|---|
| `record_experience(gathering_id)` | **由状态机在 Completed 时自动调用** |
| `get_relation(user_a, user_b)` | 一段关系的共同经历 |
| `list_relations(user_id)` | 我的搭子列表 |
| `dissolve_relation(relation_id, by_user)` | 解除 |

**数据结构约束（这是伦理红线的技术保障）**

```python
class SharedExperience:
    relation_id: str
    participants: list[str]
    gathering_type: str        # 比赛组队 / 羽毛球 / 健身 / DDL冲刺
    occurred_at: datetime
    outcome: Literal["completed", "interrupted"]
    common_grounds: list[str]  # 同上的课、共同跨专业方向
    # 没有 rating / impression / tags / note 字段 —— 且永远不加
```

> **不记录评价不是靠代码审查保证，是靠数据模型里没有那个字段保证。**
> 一旦存在评价字段，它迟早会被某个需求填满，然后产品就变成了 F17 禁止的私下评分系统。

**其他约束**
- 按**关系**建索引，不按人——避免退化成通讯录
- 一次局需为所有成员两两写入关系，**保证事务一致性**
- 双方看到的内容必须完全一致
- **不提供任何跨关系聚合查询**（无"最常一起的人"、无关系数量排序）

#### 3.8.4 阿凑记忆调用（F30）

| 能力 | 说明 |
|---|---|
| `recall_for_intent(user_id, intent)` | 用户已表达意图时，召回相关搭子 |
| `recall_for_opener(gathering_id)` | 成局时生成破冰材料 |
| `recall_for_goal(goal_id)` | 共同目标进度播报 |

**唯一判断标准**

> **记忆用于降低用户已有意图的摩擦，不用于制造用户没有的意图。**

**架构强制**：这三个函数**都需要传入一个当前上下文**（intent / gathering / goal）。**不存在无上下文的召回接口**——因此主动召回在架构上不可实现。

#### 3.8.5 退场协议（F20）

| 能力 | 说明 |
|---|---|
| `exit_protocol(gathering_id)` | 生成退场消息并降低 AI 存在感 |
| `measure_exit_success(gathering_id)` | 24h 内是否产生双向对话 |

**约束**：退场后阿凑只在四种情况出现——提醒、改约、补位、被 @。**不存在主动发消息的定时任务。**

### 3.9 `competitions/` 赛事库 `[V2.1 新增]`

**职责**：摄取外部赛事快照，维护经核验的赛事库。

| 能力 | 说明 |
|---|---|
| `ingest_snapshot(path)` | 摄取快照文件，**幂等** |
| `verify_gate(item)` | **核验闸门**——只放行状态为「可行动」的条目 |
| `map_tracks_to_skills(item)` | 赛道/任务 → 能力标签（**复用 F2 标签体系**） |
| `dedupe(items)` | 按赛事唯一标识去重（同一赛事可能多来源） |
| `expire_sweep()` | 过期自动下架，保留历史用于"追踪下一期" |
| `list_actionable(filters)` | 对外查询——**只返回已核验条目** |
| `get_required_skills(competition_id)` | **F7 组队匹配的"所需能力全集"输入** |
| `get_team_constraints(competition_id)` | 队伍人数等约束，F7 约束项 |

**形态约束（决议八）**

```
外部采集流程（定期运行，含核验去重）→ 结构化快照文件
                                      ↓
             ingest_snapshot（定时任务，只做清洗映射）
```

**不在服务内做实时爬取。** 采集需要判断与人工介入（社交线索须回原文核验），责任归外部流程；产品侧只消费已核验快照。

**关键约束**

| 约束 | 说明 |
|---|---|
| **核验闸门** | 未核验线索**永不进入产品**——用户看到不存在的比赛，伤害大于看不到比赛 |
| **标签空间统一** | 赛道映射必须落在 F2 的课程能力标签空间，否则 F7 覆盖度算不出来 |
| **报名不代办** | 只提供跳转官方入口，**无提交能力**（F27 红灯） |
| **摄取隔离** | 先落暂存表再切换，摄取失败不影响线上数据 |

**数据模型**

| 模型 | 关键字段 |
|---|---|
| `CompetitionEvent` | id, 唯一标识, 名称, 核验状态, 报名截止, 提交截止, 赛程, 线上线下, 地点, 奖励, 报名链接, 原文链接, 优先级, 个人/团队形态, 报名方式与步骤, 费用说明, 推荐等级, 核验时间 |
| `CompetitionSkill` | competition_id, 能力标签, 权重 |
| `CompetitionConstraint` | competition_id, 队伍人数上下限, 参赛资格 |

### 3.10 `actions/` 校园动作出口

**职责**：Action Schema 定义与校验，调用 hermes 的**唯一出口**。

| 能力 | 说明 |
|---|---|
| `preview(action, params, user_id)` | 生成预览，落快照 |
| `execute(action, params, gathering_id)` | **内部校验全员确认后才置 confirm** |
| `rollback(action_id)` | 失败回滚 |

**三条铁律（决议四）**
1. `confirm` 只能由服务端在校验业务条件后置位；请求体带上来的一律丢弃并记安全事件
2. 没有 Previewed 就没有 Executed
3. 执行前比对参数与预览快照，不一致则中止

**业务代码不得绕过本模块直接触达 hermes 或 CLI。**

---

### 3.11 `notify/` 通知

| 能力 | 说明 |
|---|---|
| `push(user_id, type, payload)` | 推送 |
| `sync_calendar(gathering_id)` | 仅在 Executed 后写日历（F12） |
| `revoke_calendar(gathering_id)` | 改约/取消时同步 |

**明确不实现的推送类型**
- 召回类（"好久没来"、"关心你"）
- **基于共同经历的召回**（"你们好久没一起打球了"）
- 任何以提升活跃度为目的的推送

> 这些不做成"配置为关"，是**根本不实现对应的任务**。

## 7. LLM 使用边界

**全系统只有三个 LLM 出口：**

| # | 用途 | 输出约束 |
|---|---|---|
| 1 | 意图编译（F6） | 严格 schema，校验失败走澄清 |
| 2 | 理由生成（F9） | 自由文本，但只读不执行 |
| 3 | 开场信息 / 记忆召回文案（F29 F30） | 自由文本，**输入受限于已有上下文** |

**LLM 绝不参与：**
- 匹配打分（F7）
- 命令行拼接与执行（决议三）
- `--confirm` 决策（决议四）
- 降级方案生成（F13 用预置规则）
- 主动召回（F30 架构上不可实现）

## 8. 隐私强制点

**这些必须在服务端强制，不能依赖客户端不显示。**

| 规则 | 服务端实现方式 |
|---|---|
| 不下发他人课表 | `intersect_windows` 返回结构无 user_id 字段 |
| 不下发他人等级 | 无对应接口 |
| 未满员不可见报名情况 | 查询层过滤，且不保留可查询视图 |
| 不提供同课同学名单 | 同课关系只存在于匹配语料，无列表接口 |
| 无实时在场者视图 | 不采集、不存储位置与在场数据 |
| 不记录人际评价 | 数据模型无评价字段 |
| 无排行榜 | 无排序聚合接口 |
| 无陌生人搜索 | 无用户搜索接口 |

> **通用原则：能力不该存在时，正确做法是不实现它，而不是实现后加权限判断。**
> 不可达优于可达但被拦截。

## 10. 迭代路线

| 阶段 | 范围 | 判据 |
|---|---|---|
| **P0 答辩** | identity / profile / schedule / intent / matching / gathering / actions / collab(空间+对话) | 跑通 意图→匹配→确认→真实预约→退场→人的对话 |
