# 噜噜成局 · iOS 设计交接提示词（工程代号 ONE MORE）

> 版本：V2.1  
> 适用对象：产品设计、交互设计、原型生成工具  
> 范围：iOS App 端，不包含后台管理 Web、不包含服务端实现、不定义视觉风格

## 文档核对结论

1. 产品功能应按 **F1–F31** 交接；若旧副本仍写“F1–F30”，应以当前 V2.1 正文和索引中的 F1–F31 为准。
2. 认证方式以 F1 和 iOS 指南为准：**企业微信扫码认证**。产品方案 6.1 中的 `WKWebView/CAS` 是遗留描述；客户端不得出现校园密码输入框。
3. iOS 指南当前实际包含 **74 个有编号的设计节点**：A 8、B 18、C 4、D 8、E 17、M 10、O 4、G 5。原“56 个页面”及页面树中的“B 层 13 页”是扩充 F28–F31 前后的旧统计。交接时应覆盖全部 74 个节点；其中部分是容器、浮层、Sheet 或状态规范，并非独立全屏页面。
4. iOS 端职责只有：**输入、展示、确认、系统日历/通知集成**。匹配、多人空档计算、信任计算、状态流转和执行授权判断均由服务端完成。

## 可直接复制给设计团队或设计生成工具的提示词

```text
请为 iOS App「噜噜成局」完成全量产品与交互设计交接。工程代号继续使用 ONE MORE；「差一个」保留为中央成局动作。此次只定义信息架构、页面功能、流程、状态、权限、反馈和组件，不指定颜色、字体、插画、品牌视觉或其他设计风格。

一、产品定义

1. 产品定位：中山大学校园成局智能体。
2. 核心主张：AI 不介绍人，AI 促成事。
3. 产品最小单元是“局”，不是“人”。局可以是一次羽毛球、一次比赛筹备会、一次 DDL 冲刺、一次活动同行，或一个持续数周的共同目标。
4. 产品目标：把用户目标、真实空档、课程背景和校园资源组合起来，匿名凑齐合适成员，完成多人确认、校园预约、日历同步和局后协作。
5. 三条产品原则：
   - AI 承担表达需求、匿名试探、协调时间、凑齐人数、预约执行和失败处理，降低开口与退出成本。
   - 关系只能通过共同完成一件事产生，不通过刷人、搜索、加好友产生。
   - AI 是媒介，不是社交对象；阿凑在成局前积极，成局后退场，把对话空间让给人。

二、客户端边界与两个 AI

1. iOS 端只负责输入、展示、确认、EventKit 日历、APNs 推送和深链。
2. 客户端不做匹配打分、不计算多人空档、不直接连接校园系统或 CLI、不持有校园密码、不自行决定真实操作是否可执行。
3. 两个 AI 必须在产品结构上分开：
   - hermes：个人校园工具，常驻“今天”Tab；查询课表、DDL、场地、班车等，只做工具调用，不闲聊，不持有人际记忆。
   - 阿凑：跨用户成局助手，通过中间“⊕ 差一个”进入；负责编译意图、促成局、解释匹配、协调确认，成局后淡出。
4. 不得把 hermes 与阿凑合并成同一个聊天窗口。

三、用户身份、等级和功能权限

需要覆盖以下用户状态，并给出各状态下页面可见性、入口状态、拦截说明与下一步：

1. T0 访客：未认证；可浏览免登录的活动、宣讲会、招聘会和已核验赛事；加入局、组队或预约时触发认证，认证后返回原任务。
2. T1 已认证同学：完成扫码认证和画像初始化；可浏览公开局、创建意图卡、加入 3 人及以上的低风险局、同课破冰局和 DDL 冲刺局。
3. T2 靠谱同学：完成 3 次有效成局、准时确认率达标且近期无临期爽约；解锁比赛/项目组队池、自行发起局、2 人局、跨院系匹配和 AI 代理预约。
4. T3 组局者：完成 10 次有效成局并满足发起与复局条件；解锁长期共同目标、周期性固定局、6 人以上局和补位快速通道。
5. T4 校园主理人：组织者认证或受邀；解锁官方局、批量名额、活动管理台和局模板。
6. 等级只对本人可见；其他用户的等级永远不显示。局的最低准入等级可以显示。
7. 等级解锁的是能力，不是荣誉身份。等级不足时必须解释还差什么，并提供能立刻完成的低风险场景入口。
8. 降级只通知本人，展示原因、观察期、恢复条件和申诉入口；不向他人显示任何标记。
9. 社交总开关默认关闭。关闭时“今天”和“我”可正常使用，公开局、差一个、我的局入口置灰并解释；免登录内容和外部缺口卡仍可只读浏览。

四、主导航与信息架构

主 TabBar：
[今天] [公开局] [中间“⊕ 差一个”] [我的局] [我]

附加入口：
1. T4 用户从“我”进入主理人台。
2. 缺口卡使用 Universal Link 进入指定局。
3. 推送深链进入待确认、待授权、执行结果、协作空间、群聊、关系详情、重新授权或等级详情。
4. 所有需认证的深链都要保存原始目的地，认证完成后返回原页面。

五、全量功能 F1–F31

F1 统一身份认证：企业微信扫码；展示二维码、有效期、倒计时、刷新、等待扫描、已扫描待确认、成功、超时、取消、失败与重试；App 进后台后再回来继续恢复登录会话；不出现密码框。

F2 培养方案与选课初始化：读取培养方案、已修/在修课程和课表，生成学科域、能力标签、课程社群和可用时间；只使用“修过什么”，绝不使用或展示成绩、绩点。

F3 跨专业选修信号：高亮主动跨专业选修、辅修或双学位形成的兴趣域；标签区分“已验证·选课”“跨专业选修”“自述”。

F4 同课同学连接：课程详情可发起“和同课的人开个局”；不得提供同课同学名单，只有成局后才能展示真实共同课程作为破冰理由。

F5 场景化“差一个”触发：在查空场、研讨室、作业 DDL、赛事、活动、组会等真实节点出现克制的成局建议；同场景 N 天内不重复，明确忽略两次后永久停止该场景，同时最多一张触发卡，可关闭。

F6 AI 意图卡：自然语言或语音输入，最多两轮澄清，生成结构化意图卡；字段含局类型、目标、我的能力、所需角色、目标强度、可用时间、校区、人数、社交模式、安全偏好和截止时间；每项显示来源并允许按规则编辑。

F7 双模式匹配：搭子场景求相似，比赛/项目组队求能力互补。客户端不展示打分过程，只展示可理解的匹配结果和“为什么是你们”；组队场景要表达角色覆盖与能力缺口。

F8 共同空档：只展示自己的可用时间和服务端返回的共同候选时段、可行人数、场地可用性；不得展示任何成员的原始课表或“谁在哪个时段没空”。

F9 静默成局：招募未满员时不显示报名人数和报名者；满员后才进入多人确认并公开必要身份；未满员自动结束，不出现“某人拒绝了你”等归因文案。

F10 多人确认协议：满员后每人分别确认；显示局信息、场地状态、匹配理由、已确认人数和确认倒计时；支持确认参加、提议改时间、退出。所有真实操作都必须经过“预览—授权—执行”，全员确认前执行按钮不可用。

F11 校园行动执行：支持课程/课表、作业 DDL、研讨室、体育场馆、组会/课题、宣讲会/招聘会、班车等查询；研讨室、场馆、部分科研资源支持预览和授权预约；赛事报名、宣讲会报名等不代办，只跳转官方入口。

F12 日历与提醒：仅真实预约成功后请求并写入系统日历；包含时间、地点、成员数和协作空间深链；改约或取消后同步更新/删除；允许关闭日历写入，仅保留 App 推送。

F13 补位与容错：成员退出后缺口回池；补位者只能看到加入后的必要信息，不回溯历史协作记录；补位失败提供预设降级方案；场地失效时重新选择相邻时段并重新确认。

F14 信任等级：本人可见 T0–T4、升级进度、达标条件和当前能力。

F15 等级解锁：设计完整能力解锁表；在受限入口显示需要的等级、具体差距、推荐的下一步和直达入口。

F16 降级与恢复：本人看到降级原因、受影响能力、观察期、恢复条件、申诉；不公开处罚。

F17 可见性：只显示自己的等级，绝不显示他人的等级、标识或排行榜。

F18 信任事件：按时确认、预约成功、完成确认和复局形成正向记录；提前 24 小时以上取消不受惩罚；临期退出、确认后未出现、有效举报触发影响。完成页只确认“事情是否完成”，不得做成员评分。

F19 轻协作空间：成局后提供集合时间、地点、路线、AI 开场信息、群聊、议程/规则、角色、待办、成员、改约、补位、取消和举报；单次局结束 7 天后收起协作信息，但保留对话与共同经历。

F20 AI 退场：成局后展示一次退场消息，随后阿凑只在提醒、改约、补位或被 @ 时出现；不得主动闲聊、关心、制造话题或召回；hermes 不进入局内群聊。

F21 复局与共同目标：局后提供“原班复局”“保留部分成员再差一个”“结束”；结束不通知其他人。支持长期目标、自动进度、里程碑、下次行动和克制的进度播报。

F22 可分享缺口卡：生成不含分享者身份的卡片图和深链；支持系统分享、微信、朋友圈；接收者可匿名查看和加入；未登录时先认证再返回；过期显示友好状态和相似局。

F23 组织者供给：T4 可创建官方局、固定时间地点人数、批量名额、查看报名与到场、复制周期局模板。

F24 隐私硬约束：社交默认关闭；无实时在场者；双向确认前身份最小化；原始日程永不公开；他人等级永不公开。

F25 场景敏感度：图书馆自习区、健身房器械区不提供现场连接，只允许到场前组队和结束后复盘；球类场地、研讨室、赛事与活动可走完整成局流程。

F26 线下安全：初次局优先公共校园空间；默认 3 人及以上；2 人局需 T2 且双方额外确认；支持同性局、人数下限、身份公开时机；退出、拉黑、举报始终可到达；一次有效举报永久切断未来匹配。

F27 凭证与数据边界：分项授权课表、培养方案、选课记录和代理预约；每项可撤回并说明将清除的派生数据。请假、简历/岗位投递、勤工助学、离返校登记、选课、成绩、支付等功能在客户端不得出现代理执行入口。

F28 人际对话：满员确认后开放局内群聊，支持文本、图片和位置；搭子关系可长期对话；支持 @阿凑调用订场、查资料、加日程等工具，用完即退；不存在陌生人私聊、好友申请、加好友、用户搜索、拉人进群、群二维码、已读回执、在线状态、正在输入、虚拟礼物。

F29 共同经历账本：Completed 后自动生成做过什么、次数、时间、结果、共同点和目标进度；完全零手动；只记事实，不记“靠谱、话多、迟到”等评价；共同参与者看到完全一致的内容；不得按人聚合成排行榜。

F30 阿凑记忆调用：只在用户已经表达相关意图、新局生成破冰信息、共同目标播报三个上下文中被动使用共同经历；不得用记忆主动推送“好久没一起……”或生成月度/年度关系回顾。

F31 赛事信息库：访客也能浏览已核验且可行动的赛事；支持方向、线上/线下、截止时间、可组队筛选；展示赛事名称、赛道、赛程、组队规则、提交要求、奖励、截止、所需能力；“组队”为主任务并预填意图卡，“去官网报名”为外部跳转；未核验线索不显示。

六、完整页面与设计节点

A 层：启动与准入（8）

A1 启动路由：品牌闪屏和无感路由；处理无令牌、待认证、待初始化、社交关闭、正常态和待处理深链；不人为延长启动。
A2 价值引导：三段信息，可跳过；说明不是交友软件、零填表画像、凑不齐无人知晓。
A3 扫码认证：二维码、倒计时、刷新、打开企业微信/扫码说明、状态反馈、后台恢复、超时/取消/失败重试、“为什么需要授权”。
A4 授权范围：课表、培养方案、选课记录、代理预约四个独立授权；解释用途、隐私和降级结果；全部可跳过；突出“不读成绩”。
A5 画像初始化进度：读取培养方案、扫描全学期课表、生成能力标签、识别跨专业选修；分步展示结果；可后台继续；每步可单独重试。
A6 画像确认：只读认证事实、能力标签及来源、跨专业选修、个人可用时间预览；允许隐藏已验证标签及增删自述标签；无成绩。
A7 社交开关：在个人工具已可用的前提下单独询问是否进入社交池；默认关闭，不强迫开启。
A8 系统权限：不要启动时集中索权。首次成局时申请通知，首次预约成功时申请日历；语音、图片、位置等权限也在用户发起相应动作时再处理允许、拒绝、稍后和去设置状态；位置只用于主动发送，不做实时位置或在场状态。

B 层：今天 / hermes（18）

B1 今天首页：hermes 问答入口、待确认/待授权/重新扫码待办、课程与已成局日程时间轴、最多一张场景触发卡、课表/作业/研讨室/场馆/活动/班车/赛事工具入口；待办空时保留为空，不用推荐填充。
B2 hermes 问答：工具型对话、结构化课程/空档/DDL 结果卡、跳转具体工具；闲聊时收敛到可执行事务；写操作只生成预览，不能直接执行。
B3 我的课表：周切换、网格课表、本周概览、缓存更新时间、调课高亮、下拉增量校验及限频；只显示本人课表。
B3.1 课程详情：课程、教学班、相关 DDL、“和同课的人开个局”；不显示同课人员。
B4 作业与 DDL：未完成作业按截止时间排列，临近项提供“今晚开冲刺局”。
B4.1 作业详情：作业信息和“开一个 90 分钟冲刺局”，跳转预填意图卡。
B5 体育场馆：校区、场馆类型、日期筛选和空场结果；空场时可转入找搭子。
B5.1 场馆时段选择：选择具体时段；个人预约进入 B11，多人预约进入 D3。
B6 图书馆研讨室：房型、楼层、日期、空档；可转入讨论小组。
B6.1 研讨室时段选择：选择时段并提前展示最短/最长时长、时间间隔等预约规则。
B7 活动/宣讲会/招聘会：免登录列表，支持必要筛选和状态；作为访客真实内容入口。
B7.1 活动详情：活动信息、官方报名跳转、同行/会前准备/会后复盘局入口；明确报名需本人完成。
B8 组会与课题：列表、详情、查询与支持范围内的预约或同行入口。
B9 班车：校内班车和跨校区岐关车查询，为跨校区局展示通勤可行性与行程入口。
B10 场景触发浮层：单场景限频、忽略两次永久停止、同时最多一张、可关闭、服务端文案与客户端兜底。
B11 个人行动预览：动作摘要、参数明细、影响说明、授权执行、取消；个人动作也不得跳过预览。
B12 赛事库：方向、线上线下、报名截止、是否可组队筛选；即将截止区；只展示已核验可行动赛事；每张卡有组队入口。
B12.1 赛事详情：赛程、组队规则、提交要求、奖励、能力标签、报名入口；团队赛显示“组队”并预填角色缺口，个人赛显示“找备赛搭子”。

C 层：公开局（4）

C1 公开局列表：校区、类型、时间、准入等级筛选；卡片展示目标、时间、校区、人数进度、门槛和缺口角色；不显示任何成员身份与成员等级。
C2 公开局详情：目标、时间地点、人数进度、门槛、匿名角色构成、“我来”；等级通过后进入招募或待确认，未通过进入 C3。
C3 准入门槛说明：说明所需等级、本人具体差距、最容易完成的低风险局，并直接进入 D1。
C4 缺口卡落地页：支持未安装 Web 落地、已安装深链、未登录认证后返回、已过期状态和相似局；加入链路尽量短。

D 层：⊕ 差一个 / 阿凑（8）

D1 意图输入：大输入框、语音输入、打球/自习/DDL 冲刺/比赛组队/活动同行模板和示例；支持从课程、作业、场地、活动、赛事带入预填上下文。

七、必须完整设计的端到端流程

1. 首次使用：价值引导 → 游客浏览 → 扫码认证 → 分项授权 → 画像初始化 → 画像确认 → 社交开关 → 今天首页。
2. 比赛互补组队：赛事库 → 赛事详情 → 组队 → 预填意图卡 → 招募 → 满员确认 → 共同空档/研讨室 → 行动预览 → 全员授权 → 预约成功 → 日历 → 协作空间 → 阿凑退场 → 人际对话 → 完成/复局。
3. 运动搭子：查场地 → 选时段 → 找搭子 → 相似匹配 → 确认 → 场馆预览与预约 → 提醒 → 完成 → 再来一次。
4. 同课 DDL 冲刺：课表或作业 → 课程/作业详情 → 预填 90 分钟冲刺局 → 同教学班匿名匹配 → 确认 → 协作 → 完成确认。
5. 活动同行：免登录活动 → 活动详情 → 跳官方报名或发起同行/会后复盘 → 成局；认证后须返回原活动。
6. 分享获客：分享缺口卡 → Universal Link/Web 落地 → 匿名查看 → 我来 → 认证 → 回到本卡 → 加入 → 成局。
7. 异常修复：成员退出、确认超时、场地被占、登录失效、补位失败、改约、取消、执行回滚分别形成闭环。
8. 关系沉淀：Completed → 自动共同经历 → 搭子列表/详情 → 对话或再来一次 → 单方静默解除。
9. 信任漏斗：T1 尝试高承诺场景 → 门槛说明 → 完成低风险局 → 升至 T2 → 返回并继续原组队任务。

八、局状态机与客户端表现

必须按服务端下发状态设计，不由客户端推断：

1. Draft：意图草稿，可编辑、发布或放弃。
2. Pooling：匿名招募中，可撤回、分享、查看倒计时；看不到报名进度。
3. Tentative：达到人数，分别确认；可确认、改约或退出。
4. Confirmed：全员确认，等待生成动作预览或重新授权。
5. Previewed：参数快照已生成，允许授权执行；参数变化则预览作废。
6. Executed：真实校园操作成功，展示凭证并写入日历。
7. Active：局进行中，展示协作空间和群聊。
8. Completed：确认完成，自动沉淀共同经历并给复局选择。
9. Recurred：已基于原关系生成新局。
10. Archived：协作信息收起，对话和共同经历按关系规则保留。

同时设计状态变化中的刷新、WebSocket 推送、前后台切换、重复点击、幂等返回和失效页面处理。

十、系统权限、通知、缓存与失败状态

1. 权限按价值发生时申请，不集中索取：通知在首次成局，日历在首次预约成功，麦克风/语音在首次语音输入，照片/位置在首次发送对应内容。
2. 需要设计权限未决定、允许、拒绝、受系统限制和去设置后的返回状态。
3. 推送及深链：待确认→E3；待授权→E5；执行成功→E6；局前 T-24h/T-2h→E7；补位邀请→C2；重新授权→G3；等级变化→M3；群聊→E14/E16；静默解散若推送则无深链且使用中性文案。
4. 同一会话消息推送合并、限频、弱提示；不做高频红点轰炸。
5. 明确不发：好久没来、关心你、新用户加入、基于共同经历的主动召回、月度/年度关系回顾。
6. 缓存表现：课表长期缓存并显示更新时间；画像长期缓存；局列表/详情短缓存且状态推送后失效；场地空档不缓存；信任等级在成局完成后刷新；离线或服务熔断时读页面显示缓存时间，写操作停留在可恢复状态。
7. 五类执行失败：登录失效→重新扫码；资源冲突→重选时段；限流/维护→稍后自动重试或缓存降级；参数错误→中止并给通用反馈；未知→通用反馈与重试。不得展示原始错误、堆栈或校园系统报错。
```
