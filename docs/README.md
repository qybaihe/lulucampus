## V2.1 八条架构决议

1. **hermes 与阿凑是两个 AI，物理分离** — 一个拼命干活，一个干完就走
2. **hermes 是「一份状态 + 无状态执行器」** — 产品语义不等于部署形态
3. **LLM 不拼命令行** — 中间必须有 Action Schema 白名单
4. **`--confirm` 绑定在多人确认协议上** — 安全总闸在服务端
5. **行动能力三档分级** — 红灯项在架构上不可达
6. **课表是基础设施** — ETL + 缓存，不现查
7. **对话开放给人，不开放给 AI** — 关系只能靠共同经历产生
8. **外部数据源走快照摄取** — 采集与摄取责任分离，产品只消费已核验数据

## 两个 AI

```
        hermes                          阿凑
  ┌──────────────────┐          ┌──────────────────┐
  │ 你私有的执行器     │          │ 跨用户的撮合者     │
  │ Layer 1 行动层    │          │ Layer 3 成局引擎  │
  │ 越常用越好         │          │ 越早退场越好       │
  │ 「今天」Tab 常驻   │          │ 「⊕」入口，成局后淡出│
  └──────────────────┘          └──────────────────┘
```

## 三条最容易被做错的红线

1. **不可达优于可达但被拦截** — 能力不该存在时，不实现它，而不是加权限判断
2. **对话只看是否发生，不看多寡** — 一旦优化对话量，就会长出让人多聊的机制
3. **共同经历只记事实，不记评价** — 靠数据模型没有那个字段来保证，不靠代码审查
